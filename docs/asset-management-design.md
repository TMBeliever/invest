# 资产管理 (Asset Management) 极简 MVP 设计方案

## 1. 核心定位

帮助用户**一个页面掌握全部身家**——不管是银行存款、股票、基金还是其他资产，统一录入、自动算账、一目了然。

### 设计原则
- **多品类统一管理**：存款、股票、基金、理财、其他资产，全部纳入同一体系。
- **输入极简**：每类资产只需填最少的必要字段（如存款只填金额和利率，股票填代码/数量/成本）。
- **智能自动算账**：股票和基金自动接入实时行情计算最新市值，存款和理财按利率自动算预期收益。
- **架构预留扩展**：后续可与红利测温、财报诊断等已有模块联动。

---

## 2. 资产分类体系

按照实际投资品种，设计 5 大资产类别：

| 类别 | 标识 | 说明 | 必填字段 | 自动计算 |
|------|------|------|----------|----------|
| 💰 银行存款 | `DEPOSIT` | 活期/定期/大额存单 | 金额、利率(%)、到期日(定期) | 预期年利息收入 |
| 📈 股票 | `STOCK` | A股个股持仓 | 代码、股数、成本价 | 实时市值、浮盈、股息率、预估年分红 |
| 📊 基金 | `FUND` | 公募基金/ETF | 基金代码、份额、成本净值 | 实时净值、最新市值、浮盈 |
| 🏦 理财产品 | `WEALTH` | 银行理财/券商收益凭证 | 金额、预期年化(%)、到期日 | 预期年收益 |
| 📦 其他资产 | `OTHER` | 黄金/国债/房产等 | 名称、当前估值 | — |

## 4. 数据库设计 (`SQLite`)

一张统一的 `assets` 表，通过 `category` 字段区分资产类型：

```sql
CREATE TABLE IF NOT EXISTS assets (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    category TEXT NOT NULL,              -- DEPOSIT / STOCK / FUND / WEALTH / OTHER
    name TEXT NOT NULL,                  -- 显示名称 (如 "招商银行活期", "600036 招商银行")
    code TEXT,                           -- 股票/基金代码 (存款和其他类可为空)

    -- 通用字段
    amount REAL,                         -- 金额 (存款本金/理财本金/其他估值)
    
    -- 股票/基金专用
    shares REAL,                         -- 持股数量/基金份额
    cost_price REAL,                     -- 买入成本价/成本净值

    -- 存款/理财专用
    annual_rate REAL,                    -- 年化利率 (%)
    deposit_type TEXT,                   -- 存款子类型: DEMAND(活期) / FIXED(定期)
    maturity_date TEXT,                  -- 到期日 (YYYY-MM-DD, 定期/理财)
    
    -- 备注
    notes TEXT,                          -- 用户备注

    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**设计要点**：
- 用一张表覆盖所有资产类型，通过 `category` 区分类别，避免多表关联的复杂度。
- 不同类型的资产只使用属于自己的字段，其余为 `NULL`（如存款不需要 `shares` 和 `cost_price`，股票不需要 `annual_rate`）。

## 5. 自动计算逻辑

不同资产类型的市值与收益计算方式不同：

| 资产类型 | 当前估值 | 浮盈/浮亏 | 预估年收益 |
|----------|----------|-----------|------------|
| 💰 存款 | `amount` (本金即市值) | 无浮盈概念 | `amount × annual_rate / 100` |
| 📈 股票 | `shares × 实时现价` | `(实时现价 - cost_price) × shares` | `市值 × 实时股息率 / 100` |
| 📊 基金 | `shares × 实时净值` | `(实时净值 - cost_price) × shares` | 无 (或基于历史年化估算) |
| 🏦 理财 | `amount` (本金即市值) | 无浮盈概念 | `amount × annual_rate / 100` |
| 📦 其他 | `amount` (手动录入估值) | 无 | 无 |

**汇总公式**：
- **总资产** = Σ 各项资产估值
- **总浮盈** = Σ 股票浮盈 + Σ 基金浮盈
- **预估年总收益** = Σ 存款利息 + Σ 股票分红 + Σ 理财收益
- **资产项数** = COUNT(assets)

## 6. 后端 API 设计 (`server/app/api/assets.py`)

> 独立挂载到 `/api/assets`，与现有 `/api/portfolio`（红利核心-卫星组合）互不影响，两者是并行的两套资产视图。

4 个极简 RESTful 接口：

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/assets/summary` | 获取资产总览（汇总 + 全部资产列表 + 饼图数据） |
| `POST` | `/api/assets` | 添加新资产 |
| `PUT` | `/api/assets/{id}` | 修改资产 |
| `DELETE` | `/api/assets/{id}` | 删除资产 |

### 股票/ETF 实时数据来源

- **场内交易品种**（A股股票、ETF，如 510300）：复用 `akshare_client._batch_tencent_quote()`，与个股详情页同一数据源，返回的 `price`/`dividendYield` 字段直接使用。
- **场外开放式基金**（非场内 ETF，如实际申赎的公募基金）：本期 MVP 不支持实时净值自动拉取，`currentPrice` 由用户手动维护，`annualIncome` 不计算。若后续需要，可接入 AKShare `fund_open_fund_info_em()`。

## 7. 前端页面实现 (`apps/web/app/assets/page.tsx`)

> 独立新页面，不复用/不改动现有 `/portfolio` 页面（红利核心-卫星组合保持不变）。Sidebar 新增「我的资产」导航项。

- **顶部汇总卡片**：4 个核心指标（总资产、总浮盈、预估年收益、资产项数）。
- **资产配置饼图**：ECharts 环形图，展示 5 大类资产占比分布。
- **资产明细列表**：SegmentedTabs 按类别切换 + 全部视图，使用 HeroUI Table 组件。
- **添加/编辑弹窗**：根据选择的资产类型动态切换表单字段。
